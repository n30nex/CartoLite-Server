# End-to-end reliability and performance audit — 2 October 2026

## Scope and evidence

This review covers Canada and Worldwide from MQTT input through normalization, decoding, private resolution, public state, checkpointing, HTTP/SSE delivery, Map/Netgraph rendering, Follow/audio, preferences, packaging and release. Canada Labs, the Android shell and the live Canada service are also included.

Baseline: Canada 0.15.2 (`f2b4bdff314094c22749819ddc6817d545aa0fa0`); Worldwide 0.6.2 with release-workflow maintenance at `81e36352d03c023487ccc03626bfa8459959f4f6`. The corrective releases are Canada 0.15.3 and Worldwide 0.6.3.

Source inspection and read-only operational checks established the findings below. All automated builds, tests, browser evidence and measurements run in GitHub Actions with synthetic fixtures. The implementation is subject to its exact-commit PR/main checks; this document does not declare a deployment complete.

## Findings fixed in this patch

| ID | Priority | Finding and consequence | Correction and evidence |
|---|---|---|---|
| B01 | P1 | Each node observation rebuilt its public representative by scanning and hashing the entire private node table. At the 10,000-node cap this makes ingest work grow with every stored node. | Maintain the representative incrementally. The full scan remains on removal, where replacement actually needs discovery. A paired 100/10,000-node benchmark compares scan and indexed updates on identical synthetic tables, with setup excluded and three samples. |
| B02 | P1 | Multiple region records share one public identity, but every alias could emit its own node event. An older region record could overwrite the snapshot's newer position in connected browsers; a newer record without coordinates could hide a known position. | Prefer coordinate-bearing records, then the freshest alias; emit only the current representative. A representative switch bypasses the freshness throttle. Tests cover stale/new alias events, missing coordinates, removal fallback and unchanged fail-closed private hop resolution. |
| B03 | P2 | SSE reconnect replay updated state and was also dispatched as fresh packet effects, audio and Follow input. Reconnecting could create an artificial burst of apparently live activity. | Use the existing hello sequence as the atomic catch-up boundary. Apply replay to state/counts only; new packets still animate and sound. Test initial/native reconnect boundaries, Map/Netgraph with sound enabled, and Canada's Labs caption. No public field or endpoint is added. |
| B04 | P2 | Every node freshness/name update invalidated all connected route geometry even when its position was unchanged. | Only invalidate attached geometry when latitude/longitude changes or a node first appears. Node labels, freshness and inspector updates still flow. A regression distinguishes renaming from endpoint movement. |
| B05 | P1 | Cancellation could leave accepted messages in the ingest queue outside the final checkpoint. Long-lived SSE handlers could also hold HTTP shutdown open until its deadline; the error return could skip waiting for the state writer. | Close ingest admission, drain the finite accepted queue, then flush. Give HTTP requests the process cancellation context and always wait for state shutdown. Tests load the final checkpoint and terminate an active stream. This preserves accepted input, not messages never delivered by MQTT. |
| B06 | P2 | Two default installations used the same MQTT client ID. A shared broker may repeatedly disconnect them. | Generate a short random clean-session ID when configuration is blank. Explicit IDs remain unchanged. Test uniqueness/length and overrides; update Compose and installation examples. Existing operators must clear a copied shared default or choose distinct explicit IDs. |
| B07 | P2 | Image digest extraction stopped reading the producer early under pipefail, which could fail an otherwise valid candidate publication or promotion. Canada lacked the existing Worldwide controlled retry path. | Read inspection output completely before extracting the digest. Port the tag-based manual release retry to Canada while retaining version, main ancestry, successful exact-main CI and attestation checks. Promote the tested digest without rebuilding. |

The index is private to the engine. It does not supply evidence to route inference: an unpositioned or ambiguous regional hop stays unresolved. Packet classification, audio timing, route meaning, public API v2 and checkpoint v1 are unchanged.

Worldwide release verification also now upgrades from the exact published 0.6.2 digest in the anonymous-install job on both architectures. Previously this job restarted the candidate itself; the separate legacy 0.4.1 source migration test remains required.

Initial Actions medians (three samples, representative operation only): Canada at 10,000 nodes changed from 2.029297 ms / 320,032 B / 10,001 allocations to 0.1917 microseconds / 32 B / one allocation; Worldwide changed from 2.094656 ms to 0.1937 microseconds with the same allocation reduction. Sources: [Canada Go job](https://github.com/n30nex/CartoLite/actions/runs/37070813706/job/111049557273), [Worldwide Go job](https://github.com/n30nex/CartoLite-Server/actions/runs/37070821388/job/111049580955). These are not end-to-end throughput results.

## Production baseline

Read-only Canada checks on 2 October found version 0.15.2, zero container restarts since 27 September, ready MQTT/checkpoint/queue, zero dropped observations and an empty queue. One resource sample was approximately 73.5 MiB memory and 15.14% CPU; the checkpoint was approximately 3.7 MB. These are operational observations, **not** a controlled before/after performance comparison. No live traffic capture is included in this repository.

No CartoLite systemd units were registered on the Canada droplet or the Pi during this audit. The documented recurring backup/independent watchdog setup is therefore not established by those hosts. Previous release backups are not evidence of a recurring recovery service. This patch does not provision a storage account or webhook.

There is no project-operated Worldwide live target in this release scope. Worldwide acceptance uses clean and upgrade installations of the published AMD64/ARM64 candidates in Actions.

## Validation and release acceptance

Required Actions checks retain all existing limits: Go test/vet/race; frontend types/unit/build and size gates; privacy/topology contracts; synthetic ingest/load and checkpoint checks; all themes/presets and terrain/fallback recovery; Map/Netgraph/Labs desktop and mobile journeys; the full 4,000-node/7,000-route fixture; container identity/vulnerability checks; Android API 26/36 where applicable; native AMD64/ARM64 clean/upgrade Worldwide installs.

The new microbenchmark measures representative lookup/update only. Report medians and allocations from the Actions logs; do not turn its speedup into an end-to-end throughput claim.

After reviewed passing merges, tag the exact successful main revisions and promote their tested images. Canada deployment additionally requires a fresh target/digest check, encrypted off-host backup, isolated restore, exact-image cutover, public Map/Netgraph/Labs and live SSE checks, advancing checkpoints, and at least five minutes with healthy readiness and no drops/restarts. Retain the prior digest for rollback. Release/deployment receipts and Actions links provide completion evidence separately from this source audit.
